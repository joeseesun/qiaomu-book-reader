# Qiaomu Book Reader 4.0.1 产品健壮性审计

状态：功能分支候选版已在 Rockfish 真实 Obsidian 中回归；本文是 PR 审查与后续发布的证据清单，不代表已发布。

## 设计基线

本轮使用 `qiaomu-design` 的产品打磨流程，主要参考 Notion 的内容优先层级和 Claude 的温和编辑感：细边框、低饱和背景、受克制的阴影，不用重气泡和大面积品牌色。阅读内容始终是主角，AI 和恢复提示只在需要时出现。

## P0 修复

| 问题 | 风险 | 处理 |
| --- | --- | --- |
| 扫描 PDF 切到 EPUB/文字 PDF 后，AI 仍保留“无文字层”状态 | 对话上下文错书 | AI 侧栏绑定活动 ReaderView；跨书时清掉旧文本，EPUB 不再因当前是封面而被当成扫描文档 |
| 连续快速打开图书 | 旧的异步结果覆盖新书 | 新增 AbortController 加载代次，只最新任务允许提交 UI，关闭时释放 PDF 加载任务 |
| 大 PDF 或侧栏变宽时显示空白页 | 用户认为文档损坏或插件卡死 | 保留加载幕直到布局完成，先给 Chromium 一次绘制机会；检测“总页数很多但所有正文都映射到第 1 页”时自动重排一次 |
| CLI 已登录仍报“请检查登录” | 可用的 AI 被错误禁用 | 不再使用可产生假阴性的状态命令做硬门禁；点击确定后真实建立 ACP 会话并发送最小生成请求，成功才自动启用 |
| “保存 AI 回复”复用划线笔记路径 | 保存的主体变成原文 | 独立 AI 回答笔记路径，回答作为正文，问题、引用上下文和图书链接作为来源 |

## 高价值 P1

| 问题 | 处理 |

| 清空对话记录使用系统 `confirm` 且范围不明 | 改用 Obsidian 确认弹窗，明确分为“清空本书”和“清空全部” |

| lint 噪声掩盖真实问题 | 仅对明确的产品专名加白名单，`npx eslint src/` 回到 0 警告 |

## 性能与 CLI 证据

- PDF.js 文字提取：扫描样本 248 页在 73ms 完成，0 字符；报告样本 32 页在 291ms 完成，41,812 字符。首屏的主要耗时是 Chromium 固定排版，当前通过持续加载反馈与崩塌自检消除“无反应空白”。
- 真实 CLI 最小生成：Grok 首 token 15.324s / 总计 15.736s；Kimi 首 token 6.750s / 总计 6.824s。这说明 Grok 的慢主要在首次推理/连接，而不是 Markdown 渲染。
- ACP 初始化：Grok 7.866s，Kimi 1.675s，Codex 1.183s，Claude 0.802s，ZCode 2.177s；五个 provider 均成功建立会话。Grok 的 `models` 状态命令在同一台机器上误报未认证，而 `agent stdio` 真实生成成功，因此不再用前者做硬门禁。
