# 社区市场候选版与独立重写边界

## 当前结论

功能差异不等于代码独立。目前 `src/main.js` 中的分页器、ReaderView、ReaderModal、书库、设置等仍沿用并改造了上游结构；`upstream/main:src/main.js` 可核对对应实现。不能通过更名、拆文件、翻译注释或重新初始化 Git，将继承代码声明为完全原创。

[Obsidian 开发者政策](https://docs.obsidian.md/community-directory/developer-policies)要求 fork 获得原作者可公开核验的书面同意，或满足停止更新和联系等待的例外条件。继续复用原仓库实现就仍应按 fork 说明来源，不能称为独立新实现。MIT 许可证保留与市场准入分别处理，现有 LICENSE、NOTICE 和 README 鸣谢继续保留。

2026-09-05 已按维护者要求提交[俄文公开授权申请 #14](https://github.com/swayinfo/elton-reader/issues/14)，说明中文用户方向、功能改造与独立维护责任。申请待回复；未获得授权，未提交社区市场。

## 已实现：将 ACP 安装器与对话能力分离

| 项目 | 普通版 | 社区候选版 |
| --- | --- | --- |
| 构建 | `npm run build` | `npm run build:community` |
| 输出 | 根目录三件套 | `dist/community/` 三件套 |
| Claude / ZCode ACP 安装 | 保留用户主动触发的一键安装 | 不打包安装器执行模块 |
| 安装指引、复制命令 | 保留 | 保留，由用户自行在终端执行 |
| 已安装 CLI / ACP 检测、验证 | 保留 | 保留 |
| 常驻会话、流式输出、模型切换 | 共用 | 共用 |
| PDF / EPUB / 笔记 / 草稿 / 快捷提示词 | 共用 | 共用 |

- 普通版安装器为 `src/ai-acp-installer.js`；社区构建通过显式模块解析替换为 `src/ai-acp-manual.js`。不是设置开关，也不下载插件代码来重新启用安装器。
- 候选版即使内部误调用安装方法，也只返回 `acpmissing`，没有安装 subprocess 或文件写入实现。
- `build-info.json`记录构建模块清单；校验同时检查清单、通道标记和安装器特征代码。安装命令作为说明文字仍会存在，这不等于执行安装。
- 本地候选产物保持相同插件 ID 和版本，只供对比验证；不能与普通版同时安装，也不能把不同通道的三件套混在一个 Release。生成候选版不会覆盖根目录普通版或当前 Obsidian 安装。
- 正式上架前必须确定唯一的默认分支、默认构建和对应版本 tag。当前默认构建仍是普通版，**不能直接以当前仓库默认构建提交市场**。双通道的正式发布仓库/版本方案尚未确定。

## 独立新实现的开发清单（尚未开始完整重写）

不是先复制当前 main.js 再整理。应在新的代码库按产品规格实现，并逐项保存来源审计与行为验收。

1. **规格与数据兼容**：明确导入格式、页码语义、进度锚点、笔记格式、划线模型与 AI 上下文规则；用自制测试书构建夹具。为旧数据设计只读迁移和可回滚导入，不能用重写之名丢弃用户笔记。
2. **新阅读内核**：独立实现 EPUB/FB2 导入管线、资源安全边界、分页/滚动布局与锚点恢复；PDF 直接使用其自身许可允许的 PDF.js 原页渲染接口。不得复制上游 Paginator 或 ReaderView。
3. **持久化层**：独立实现进度、书签、划线、笔记与损坏恢复服务；存储边界与 UI 分离，禁止重排事件错误覆盖真实进度。
4. **新 UI 层**：重新实现书库、阅读导航、选区工具条、设置与移动端弹窗；桌面和移动端共享状态模型，不复制两套大 View。
5. **AI 模块来源审计**：现有独立文件只能作为待审计候选，不能因文件在 fork 后新增便直接断言完全原创。确认没有继承上游代码后才考虑复用；其余按规格重写。保留普通/社区安装边界。
6. **迁移与回归**：验证 EPUB、FB2、文字型/扫描/混合 PDF；进度恢复、跨书草稿、AI 保存、IME、连续搜索和尺寸变化均有自动测试；桌面及真实移动设备验收后再替换现有版本。
7. **来源与发布审计**：记录每个模块的实现来源、第三方许可证及构建来源；保留必须保留的署名。独立实现也不能预先保证官方审核结果。
